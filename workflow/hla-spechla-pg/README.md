# DōgoHLA v0.1.0

DōgoHLA is a new population-specific, pangenome-based method for HLA sequence
reconstruction. AsianPGR-derived gene sequences guide read collection, and
population haplotype graphs supply structural alleles. The method combines these
inputs with read-backed phasing, corrected phase-block linkage and guarded
reconstruction of supported noncoding indels.

Public releases: <https://github.com/biohackathon-japan/BH26-asian-hla/releases>.
The directory name `hla-spechla-pg` preserves the original experiment layout.

## Installation and execution scope

This is the research source release used for the reported experiments. It runs
in the prepared DDBJ layout encoded in the scripts. It currently requires
SpecHLA v1.0.12, vg v1.76.1, the SpecHLA command-line dependencies, IPD-IMGT/HLA
v3.65 phase references, and fold-specific panel databases and locus graphs.
Python scoring and tests use NumPy, SciPy, pysam, edlib and Biopython.

`experiment.py`, `build_refs.py` and `spechla_pg.sh` contain the original environment
paths. For another machine, adapt these installation paths and the Slurm scripts
to its environment before running. `SPECHLA_PG_ROOT` relocates the pipeline assets
and outputs only. The release does not include a portable installer or the
external IPD/SpecHLA databases.

The method uses SpecHLA components for read alignment, small-variant calling and
initial reconstruction. Cite [Wang et al. (2023)](https://doi.org/10.1016/j.crmeth.2023.100589)
and retain [the MIT notice](LICENSE-SpecHLA) when distributing those components.

## Prepare inputs

1. Install the specified tool versions and obtain their reference databases.
   The companion analysis archive contains extraction/annotation workflows and
   manifests. AsianPGR's graph archive contains the whole-MHC resource; method
   inference additionally needs the per-locus, fold-excluded references below.
2. Restore the source gene FASTAs and donor/family manifests described in
   `build_refs.py` and the analysis archive's `hla-analysis/REPRODUCIBILITY.md`.
   Per-gene FASTAs are generated by the supplied extraction/annotation workflow
   from the source MHC haplotypes. Large source assemblies and raw reads remain
   external inputs.
3. Run `build_refs.py` and `build_graph_pggb.sh` using the supplied job templates
   to create fold databases and locus graphs. Follow `IMPLEMENTATION.md` for
   preparation of the repaired phasing references with `experiment.py prepare`.
4. Populate a prepared root with `source/`, `db/foldN/`, `graphs/foldN/`,
   `reads/DONOR/r1.fq.gz`, `reads/DONOR/r2.fq.gz`, `reads/DONOR/COMPLETE`,
   `code/` and `phase/PREPARED.json`. The preparation and validation scripts
   document the precise directory contracts and verify family exclusions.

Run inside a compute allocation, using the prepared root:

```sh
python3 code/dogohla.py --root /path/to/prepared-root \
  --donor HG00658 --fold 1 --threads 4
```

`--paired` also runs native SpecHLA on the same inputs. The driver creates
`final/runs/DONOR/DogoHLA/` and the matched `DogoHLA-no-graph` ablation, with
reconstructed FASTAs, naming results, edit audits and hashed completion records.
Incomplete or invalid outputs remain inspectable. Historical remote deployment
scripts target the original DDBJ environment; they are not installation commands.

## Validation and reproducibility

From the repository root:

```sh
python3 scripts/fetch_nomenclature.py
python3 -m unittest discover -s workflow/hla-spechla-pg -p 'test_*.py' -v
```

[Development results](RESULTS-2026-09-18.md) report 36 → 57 exact whole genes
out of 128 and 22.8% fewer global sequence edits relative to saved native SpecHLA
outputs. [Implementation](IMPLEMENTATION.md) records the component controls.
[Prospective protocol](validation/20260918/PROTOCOL.md) specifies the additional
32-donor evaluation. Release v0.1.0 excludes live interim validation outputs.
The graph reconstruction step accepts confident homozygous noncoding long indels;
heterozygous structural phasing remains future work.
